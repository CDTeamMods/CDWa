Motor de Segurança

O CDWA foi desenvolvido com um motor inteligente de proteção e segurança, reproduzindo com fidelidade o comportamento de um usuário humano no WhatsApp Web.

Por que automações tradicionais falham?
Sistemas automatizados antigos disparam dezenas de mensagens em milissegundos sem enviar presença ("digitando..."), sem marcar mensagens recebidas como lidas e com assinaturas de navegadores obsoletas. As heurísticas de proteção da Meta detectam esse padrão instantaneamente.

Os 4 Pilares de Segurança no CDWA

1. Simulação de Digitação Humana

Antes de disparar qualquer mensagem de texto, o CDWA emite o evento composing (digitando...) e aguarda um tempo proporcional à quantidade de caracteres da mensagem (~40 caracteres por segundo, com variação aleatória de jitter), finalizando com paused:

  • Mensagens de texto simulam digitação humana realista.
  • Notas de voz em áudio simulam status recording (gravando áudio...) antes do upload.

2. Fila Segura Anti-Flood (Rate Limiting)

Mesmo que sua aplicação envie 50 mensagens em um loop for, o CDWA intercepta as requisições na SafeMessageQueue:

  • Introduz um intervalo variável (ex: entre 1.2s e 3.5s) entre cada disparo.
  • Limita a taxa máxima por minuto (padrão: 25 mensagens/minuto) para evitar bloqueios por rajada.

3. Confirmação de Leitura (Blue Ticks)

Humano abre a conversa, lê a mensagem e responde. O CDWA permite marcar as mensagens como lidas antes de responder: 

// Marca mensagem como lida (double blue ticks)
await sock.readMessages([{ remoteJid: jid, id: 'ID_DA_MENSAGEM' }])

4. Fingerprint de Navegador Atualizada

O CDWA se conecta simulando as versões mais recentes do Google Chrome (v131+) no Windows 11 e macOS, eliminando rejeições de protocolo por cliente desatualizado.

Como Configurar os Recursos de Segurança

Os mecanismos de segurança já vêm ativados por padrão com limites recomendados. Você pode personalizar os parâmetros no makeWASocket:

import makeWASocket, { useSecureAuthState } from '@cdteam/cdwa'

const auth = await useSecureAuthState('./auth_info', 'senha-mestra')

const sock = makeWASocket({
  auth,
  safety: {
    simulateHumanBehavior: true, // Simula "digitando..." ou "gravando..."
    rateLimit: true,             // Fila anti-flood sequencial
    maxMessagesPerMinute: 25,    // Limite máximo seguro por minuto
    minDelayMs: 1200,            // Atraso mínimo entre mensagens (1.2s)
    maxDelayMs: 3500,            // Atraso máximo aleatório (3.5s)
  },
})

Dicas Extras para Operação Segura de Bots

  • Aquecimento de Números Novos (Warm-up): Chips recém-cadastrados não devem enviar mais que 10 a 15 mensagens por dia na primeira semana. Aumente o volume gradativamente.
  • Evite Spam Não Solicitado: O maior gatilho de bloqueio são cliques no botão "Bloquear e Denunciar" por parte dos destinatários. Sempre envie mensagens apenas para quem autorizou contato.
  • Variação de Mensagens: Evite enviar exatamente o mesmo texto repetido para dezenas de pessoas seguidas; alterne saudações (ex: "Olá", "Oi", "Tudo bem?") para criar mensagens únicas.
