Cache em Memória: makeCacheableSignalKeyStore ⚡

A função makeCacheableSignalKeyStore cria uma camada de cache em memória (RAM) sobre o SignalKeyStore, reduzindo drasticamente as operações de Entrada e Saída (I/O) em disco ou banco de dados.

Otimização Essencial para Produção
Equivalente direto à função homônima do Baileys, elimina gargalos de latência causados pela leitura e decriptação contínua de arquivos de sessão no disco.

Por que o Cache é Necessário? 🤔

No protocolo Signal do WhatsApp Web Multi-Device, para cada mensagem enviada, recebida ou reação, o cliente precisa consultar e rotacionar chaves criptográficas:

  • session: Sessão Double Ratchet para cada contato ou dispositivo vinculado.
  • sender-key: Chaves de remetente para envio eficiente em grupos.
  • pre-key e signed-pre-key: Pré-chaves de estabelecimento inicial.

Em grupos movimentados ou bots com alto volume de mensagens, isso significa centenas de leituras de arquivos por segundo (fs.readFile + JSON.parse + decriptação AES). Com o makeCacheableSignalKeyStore, as chaves frequentemente usadas ficam mantidas na memória RAM, resultando em:

  • 🚀 Latência de leitura quase nula (~0.001ms em RAM vs. ~2-15ms em disco/banco).
  • 📉 Redução de 95%+ em operações de disco (I/O).
  • ⚡ Menor consumo de CPU, evitando parsing e decriptação repetitivos.

Como Utilizar (Uso Recomendado)

Basta envolver o objeto auth.keys retornado por useSecureAuthState na função makeCacheableSignalKeyStore: 

import makeWASocket, {
  useSecureAuthState,
  makeCacheableSignalKeyStore
} from '@cdteam/cdwa'

async function startBot() {
  // 1. Carrega o estado de autenticação em disco
  const auth = await useSecureAuthState('./auth_info', 'senha-mestra-opcional')

  // 2. Cria o socket envolvendo as chaves com o cache de memória
  const sock = makeWASocket({
    auth: {
      creds: auth.creds,
      keys: makeCacheableSignalKeyStore(auth.keys) // ⚡ Cache ativo!
    },
    printQRInTerminal: true
  })

  sock.on('connection.update', ({ connection }) => {
    if (connection === 'open') {
      console.log('✅ Conectado com cache de chaves ativo!')
    }
  })

  await sock.connect()
}

Opções Avançadas e Customização ⚙️

O makeCacheableSignalKeyStore possui um algoritmo de gerenciamento LRU (Least Recently Used) nativo para evitar consumo excessivo de memória, além de permitir parametrização e uso de caches externos:

1. Limite de Chaves (LRU) e TTL

Configure a quantidade máxima de itens em memória e um tempo de vida opcional:

const cachedKeys = makeCacheableSignalKeyStore(auth.keys, {
  maxKeys: 15000,           // Mantém até 15.000 chaves quentes na RAM (Padrão: 10.000)
  ttlMs: 12 * 60 * 60 * 1000 // Opcional: expira itens após 12 horas
})

2. Usando com NodeCache ou Map Customizado

Você pode passar uma instância de NodeCache ou um Map personalizado:

import NodeCache from 'node-cache'

// Usando com node-cache
const myCache = new NodeCache({ stdTTL: 3600, useClones: false })
const cachedKeys = makeCacheableSignalKeyStore(auth.keys, myCache)

// Ou usando com um Map nativo do JavaScript:
const customMap = new Map()
const mapKeys = makeCacheableSignalKeyStore(auth.keys, customMap)

Comparativo de Performance 📊

Cenário Sem Cache (Disco Direto) Com makeCacheableSignalKeyStore
Operações de E/S por mensagem 1 a 5 leituras de arquivos por envio Zero I/O (após aquecimento)
Tempo de resolução de sessão ~3ms a 18ms (depende do disco/SSD) ~0.002ms (acesso direto a Map)
Comportamento em Grupos Grandes Gargalo em rajadas de mensagens Fluxo contínuo sem travamentos
Sincronização de Estado Persistência direta Persistência assíncrona garantida

Exemplo em JavaScript Puro (CommonJS)

const { default: makeWASocket, useSecureAuthState, makeCacheableSignalKeyStore } = require('@cdteam/cdwa')

async function run() {
  const auth = await useSecureAuthState('./auth_info')

  const sock = makeWASocket({
    auth: {
      creds: auth.creds,
      keys: makeCacheableSignalKeyStore(auth.keys)
    }
  })

  await sock.connect()
}
